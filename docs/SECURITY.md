# Security and privacy model

## Offline by construction

- `src/renderer/index.html` sets a Content Security Policy with
  `connect-src 'none'`, `object-src 'none'`, `base-uri 'none'`, and no remote
  origins.
- The renderer runs with `contextIsolation: true`, `nodeIntegration: false`, and
  `sandbox: true`.
- The preload exposes a small, fixed IPC surface. The renderer cannot spawn a
  process or read arbitrary files.
- There is no telemetry, updater, analytics, remote logging, or model runtime.
- No network requests are required for any workflow path.

## Two independent gates

**Capability gate.** Each agent receives a fixed tool list:

- Lead: `job.plan`, `handoff`, `report.write`
- Scanner: `diag.run`, `handoff`
- Repair: `repair.propose`, `repair.apply`, `handoff`

The orchestrator checks the gate before each phase. Scanner cannot call a repair
tool, and a renderer message cannot widen the list.

**Approval gate.** Repair may only run a repair from the predefined catalog. The
orchestrator creates a short-lived, single-use approval token when it proposes a
fix. `ApprovalStore.consume` deletes the token before checking repair id, expiry,
or reuse, so a duplicate click, stale proposal, or replayed request cannot run a
second action.

The renderer must send the matching `proposalId` and `approve`/`decline`.
Mismatches are rejected without executing anything.

## Read-only Scanner

The Windows adapter is built from read-only PowerShell/WMI/CIM queries. Scanner
has no repair tools. Results pass through `makeResult`, which preserves the
measured status; unavailable (`skip`) is a distinct status and is rendered as
**UNAVAILABLE**, not pass.

## Data written

Reports are written to `reports/` beside the executable on the USB drive:

- `HTML` report for humans
- `TXT` report for tickets/notes
- `JSON` report with check results, proposal, decision, repair outcome, event
  timeline, and capability summary
- `audit-log.jsonl` append-only local audit entries (capped and rotated)

Reports contain local system details (computer name, OS build, hardware,
services, network addresses). Treat the USB drive as sensitive. The app never
uploads it.

If the primary folder is not writable, reports go to
`Documents\Feather AI 2 Reports`; the UI and report metadata record the fallback.

## Repair scope

The catalog is intentionally small: firewall, print spooler, audio services,
temporary files, DNS cache, and icon cache. There is no arbitrary command entry,
no downloaded script, and no model-generated command execution. Each repair
reports an outcome, details, and rollback guidance where applicable.

## Supply chain

- Runtime dependencies: Electron only.
- Dev dependencies: Electron, electron-builder.
- Artwork is generated by `scripts/generate-art.js`; no third-party art or fonts.
- The GitHub Actions Windows workflow runs `npm ci`, unit tests, the packaging
  build, and the live Windows acceptance test before publishing a release asset.
- A release is not code-signed by default. Verify the SHA-256 provided with the
  release and the repository commit before running an unsigned build.
